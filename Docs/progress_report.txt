## Phase 14.4 - Real screenshots in the in-app slide manual

Wired the user's real screenshots (previously only embedded in the docx
manuals) into the in-app slide viewer, and removed the "put screenshot here"
placeholder text from the System Overview docs.

- Extracted 24 screenshots from the 5 role docx manuals (Requester, Approver,
  PAS/HRAD, Guard, Admin), resized to fit a slide (max 1100x1200) and
  recompressed as JPEG - ~4.8 MB of source images down to ~1.3 MB, saved
  under `Frontend/Design/images/manual/`.
- `usermanual.js`: added `umImg()` (renders a captioned, click-to-zoom image)
  and `umZoom()` (fullscreen lightbox overlay). Expanded the Approver (3->5),
  PAS/HRAD (4->6), and Guard (2->4) guides to one slide per real screenshot,
  since the user captured more granular steps than the original placeholder
  count; Requester and Admin already matched 1:1 and just got real images.
- `styles.css`: `.um-figure/.um-img/.um-caption` (bordered, shadowed, capped
  at 46vh so tall portrait/mobile shots stay contained) and
  `.um-zoom-overlay/.um-zoom-img` for the lightbox. `.um-stage` switched from
  `overflow:hidden` to a scrollable max-height so image + text slides never
  clip.
- System Overview (docx/pdf, both the standalone file and the in-app
  Overview guide) no longer has "SCREENSHOT" placeholder boxes for the
  route-preview/architecture diagram, since no real screenshot exists for
  those - just the explanatory text.
- Verified in preview: every `umImg()` reference resolves to a real file (no
  orphans), all slide counts/step order walk correctly per role, images load
  with no 404s, and the zoom lightbox opens the correct enlarged image.

## Phase 14.2 - In-app User Manual as role-gated slides

Reworked the in-app manual from a single scrolling page into a Canva-style,
page-by-page slideshow, gated by role/permission.

- New `Frontend/Functions/usermanual.js`: renders into `#umRoot`. Users first
  see a picker of guides filtered to their role (Overview for everyone;
  Requester, Approver, PAS/HRAD, Guard, Admin shown only to matching roles /
  permissions, incl. canNoteGatePass and TRUCK_SCHEDULE_MANAGER). Selecting a
  guide opens it one slide at a time with Previous/Next, dot indicators, a
  slide counter, left-to-right animation, and arrow-key navigation.
- `styles.css`: slide-viewer styles (`.um-stage`, `.um-navbtn`, `.um-dot`,
  animations). `navigation.js`: `initUserManual()` on section open.
- Documentation stays only inside the manual page (not elsewhere in the app).
  The standalone docx/pdf are unchanged (the user added their own screenshots).

## Phase 13.9 - Scheduling fixes (3 items)

Three schedule-related fixes across frontend, backend, and DB.

- Calendar pending: a reservation now stays "pending" on the calendar from
  HRAD assignment all the way through the final PAS noting, and only drops the
  "Pending" tag once the pass is fully APPROVED. Before, it flipped to
  RESERVED as soon as it hit PENDING_PAS, so it looked approved too early.
  Backend change in `ApprovalRepository.cs` (reservation status). A PENDING
  reservation still blocks the vehicle, so no double-booking risk. The month
  pills and the day grid now show the word "Pending" explicitly, not just a
  colour. API rebuild + redeploy required.
- Trip type locked at HRAD: the requester already picks Hatid at Sundo /
  Hatid lang / Sundo lang on their form, so the HRAD assignment modal no
  longer lets Ms Joy re-choose it - the Trip Type selector is locked to the
  requester's choice ("Set by the requester" hint). Straight-vs-split
  scheduling for a Both trip still works. Frontend `modal.js` + a backend
  guard in `ApprovalRepository.cs` that keeps the requester's stored trip type.
- Truck schedule manager: MUAMAR (GA136, Logistics/PPC) can now manage the
  recurring weekly TRUCK schedules only - not regular cars. New role +
  permission (`fleet.truckschedule.manage`) in migration 022, backend scope
  checks in `FleetController.cs` (trucks = vehicle_type 'TRUCK'), and the
  "Manage Fixed Schedules" tool filters to trucks for him. HRAD keeps full
  access. Needs the DB migration + API redeploy.

Deploy note: frontend cache-bust bumped to `20260709-phase1311` (modal.js,
calendar.js). Run the DB setup so migration 022 applies. Backend redeploy
required.
